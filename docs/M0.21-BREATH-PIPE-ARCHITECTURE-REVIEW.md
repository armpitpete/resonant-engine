# M0.21 — Breath Pipe Architecture Review

Status: **FINAL M0.21 PASS — APPROVED**

The early M0.21 review was performed after M0.1–M0.4 to stop the architecture hardening around a conventional note/oscillator model. This document is the required **final hostile repeat** after M0.5–M0.20.

## API walk

### Pressure
**PASS.** Pressure is a first-class Event/exciter input concept, independent of MIDI/device APIs. It can arrive at an exact sample offset and then drive model-local smoothing/interaction continuously.

### Turbulence
**PASS.** Turbulence is a first-class excitation amount, not post-output noise. `Pcg32` supplies deterministic, allocation-free noise state when a future exciter needs stochastic flow.

### Continuous excitation
**PASS.** A model receives/processes every sample; no note-on or oscillator is required to create energy. Pressure/external audio/noise can persist indefinitely.

### Transient excitation
**PASS.** Trigger and NoteOn/NoteOff events coexist with continuous excitation. Plucks/strikes/bursts do not require another engine.

### Exciter reacting to resonator state
**PASS.** `ExciterInput::returned_resonator` and ordinary sample-domain routing allow returned state/energy to alter the next excitation interaction.

### Passive resonator
**PASS.** Zero active feedback plus damping/loss is legal; no active-energy requirement exists.

### Regenerative resonator
**PASS.** Feedback is explicitly model topology and can return a controlled fraction of resonator energy every sample.

### Self-sustaining resonator
**PASS.** Active/self-sustaining regimes are first-class in the terminology, ADRs and energy-state model. The architecture does not force decay to zero.

### Controlled instability
**PASS.** Musical instability is distinct from numerical failure. High/chaotic finite energy may be represented; NaN/Inf is failure.

### Feedback filtering
**PASS.** Filtering has an in-loop insertion point and is demonstrated by `FeedbackStage`.

### Nonlinear feedback
**PASS.** Nonlinearity can live inside returned-energy topology. M0 does not force it to be an output effect. Future oversampling remains model-local.

### Sample-accurate parameter movement
**PASS.** Events carry sample offsets and Engine applies them before the exact sample. `ParameterSmoother` advances inside the sample loop.

### Continuous pressure movement
**PASS.** Pressure can update sample-accurately and then be interpolated/sample-processed without a Host-specific control-rate architecture.

### Overblow-like transitions
**PASS.** There is no one-oscillator/one-register abstraction. A future resonator can change modal/register behavior as excitation/feedback state changes.

### Tuning reacting to phase changes
**PASS.** Resonator tuning is a model-level control, while the Feedback contract explicitly records that filtering/interpolation/nonlinearity alter loop phase and effective pitch. No fixed integer-delay tuning rule exists.

### Energy observation
**PASS.** Fixed-memory RMS/peak/feedback/excitation observation exists and can be read without a logging callback.

### Runaway detection
**PASS.** NaN, Infinity and large finite peak growth are observable; optional emergency containment exists without redefining musical instability.

### Arbitrary audio excitation
**PASS.** Core buffers admit external audio and ExciterInput contains an external-audio sample. A future microphone/sample stream is a Host source feeding the same API.

### Resonator as exciter
**PASS.** Resonator output/feedback taps are sample-domain values that a containing model may route to another Exciter.

### Bidirectional resonator coupling
**PASS.** Coupling ports are explicitly reserved and do not impose one-way graph direction. A containing model can solve/update coupled nodes sample by sample.

### Future graph topology
**PASS WITH SCOPE LIMIT.** M0 does not implement arbitrary runtime graphs, but Node/Edge/Resonator Graph vocabulary, coupling ports, sample-domain routing, fixed events and Host/core separation do not require rewriting the Engine to add a bounded graph container later. Graph mutation remains non-real-time configuration.

### WASM Host
**PASS ARCHITECTURALLY.** Browser wrapper can map AudioWorklet blocks/events to the same core. No Web Audio/DOM/JS dependency is in `resonant_core`; block quantum does not become feedback delay.

### VST Host
**PASS ARCHITECTURALLY.** VST3/JUCE wrapper can map sample-offset automation/audio buffers into the same core. No plugin SDK type is required by the model.

### Embedded Host
**PASS ARCHITECTURALLY.** Caller-owned buffers, fixed event storage, no required allocation/locks/OS APIs and small sample-loop stack fit a future ARM/DMA wrapper. Device drivers remain outside core.

### Steampipe leakage
**PASS.** No Steam/Pipe panel API, preset format, proprietary naming/layout or assumed proprietary algorithm appears in the core. Pressure/turbulence/excitation/feedback/damping/nonlinearity are generic physical/resonant concepts justified independently.

### Full continuum
**PASS.** Nothing in M0 creates a minimum pitched oscillator state. Zero-energy silence is legal; deterministic noise can exist below pitch; resonant feedback can emerge, self-sustain, destabilize, reorganize/overblow and return toward noise-like finite states.

## Hostile review

The final review attempted to break the design in these ways:

1. **Force block-latency feedback.** Failed: feedback lives inside model `processSample()`.
2. **Force note-on before sound.** Failed: continuous external/pressure/turbulence excitation is legal.
3. **Force one oscillator/tuned delay.** Failed: resonator contract is algorithm-neutral.
4. **Force random behavior to depend on Host entropy.** Failed: core PRNG is deterministic and seed-driven.
5. **Force Browser/VST/device APIs into the model.** Failed: dependency checks and repository boundary prohibit them.
6. **Force a single static preset snapshot.** Failed: exact-sample events and smoothers permit continuous transition behavior.
7. **Treat instability as an error.** Failed: energy model distinguishes musical instability from numerical runaway.
8. **Use graph/coupling later and require a new Engine.** No blocker found: sample ports/events/state ownership remain compatible with a bounded containing graph.
9. **Make phase/tuning compensation impossible.** Failed: tuning is model-specific and feedback phase consequences are explicit.
10. **Make failure handling unsafe.** Initial local Release review found that output clearing on an invalid block trusted the caller frame count. This was a real blocking weakness; `clearOutputs()` is now bounded by the prepared/global maximum before final approval.

## Recorded non-blocking weaknesses

- M0 proves Host feasibility, not production WASM/VST3/ARM binaries.
- M0 maximum is two channels; multichannel resonator-network I/O is a later extension.
- `Exciter`/`Resonator` C++20 concepts are compatibility prototypes, not a frozen 1.0 ABI.
- the reference feedback probe is not perceptually convincing and must not become the accidental first resonator specification;
- cross-platform floating-point renders are tolerance-conformant, not promised bit-identical;
- arbitrary graph scheduling/strongly typed physical coupling quantities remain later research.

None requires rewriting the M0 Engine/core boundary to begin M1.

## Final decision

**PASS. Breath Pipe architecture APPROVED.**

The full required continuum is representable without a special-case Steampipe API, host-specific DSP fork or block-latency feedback workaround.
